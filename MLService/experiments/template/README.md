# Шаблон протокола ML-эксперимента

Статус: template

Копировать в новый `MLService/experiments/<run-id>/README.md`, выбрать уникальный run ID, заменить статус на `planned` и добавить ссылку в [реестр](../README.md). Заполнить план до запуска, результаты — после. Связать с применимыми ID требований из [спецификации ML](../../docs/spec/README.md); для существенного изменения при необходимости добавить ссылку на спецификацию функции и план.

## Вопрос и критерий решения

Гипотеза; что меняется относительно конкретного baseline; задача/плоскость/сторона и mapping классов. Основная метрика и правило сравнения фиксируются до запуска, дополнительные метрики перечисляются отдельно. Численный порог проекта нельзя подразумевать по фразе «90+%».

## Данные и разбиение

Источник/версия и контрольные суммы манифеста, меток, кропов; правила исключения пропусков/ошибок; число пациентов, исследований, сторон и классов. Единица наблюдения и устойчивый ключ группы пациента. Где доступна приватная связь без раскрытия персональных данных.

Split ID/хэш, состав групп train/validation/test или всех фолдов, проверка отсутствия пересечений пациентов. Происхождение весов детектора для каждого split; оценивается готовый ROI-классификатор или вся цепочка. Недоказанная независимость явно ограничивает вывод.

## Воспроизведение и ресурсы

Commit и состояние рабочей копии (при dirty — сохранённый patch/версия исходников), entrypoint/ноутбук, точная команда и конфигурация, Python/PyTorch/CUDA и устройство, seed, preprocessing/augmentation, архитектура и checksum исходных весов. Лимит времени/эпох, место сохранения, разрешение на затратный запуск и условия остановки.

## Оценка

Правило выбора эпохи/гиперпараметров/порога и какие данные используются на каждом шаге. Baseline на тех же фолдах. Основная/дополнительные метрики, поддержка классов, confusion matrix; значения по каждому фолду, средние и явно обозначенный разброс. Доверительные интервалы, если считаются, должны учитывать группы пациентов. Список данных, не участвовавших в подборе; если таких нет — это оценка разработки.

## Результаты

До запуска: «Не запускалось; метрики отсутствуют». После: время и статус, исполненная команда, фактические метрики, сбои/пропущенные фолды, путь и checksum отчёта, предсказаний и выбранных весов. В README оставить минимальные обезличенные результаты, доступные после clone. Ignore-правила не гарантируют сохранение JSON в Git.

## Вывод

Подтверждена ли гипотеза; отличие от baseline, неопределённость и ограничения; решение и следующий шаг. Статусы: `completed` — протокол выполнен, даже без улучшения; `inconclusive` — данных недостаточно для вывода; `failed` — технический сбой, результаты не выдумывать. Изменившийся после просмотра результатов протокол требует нового run ID.
