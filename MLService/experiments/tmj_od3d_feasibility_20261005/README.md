# TMJ-OD3D V2 — проверка готовности публичной когорты

Статус: completed-negative (первый binary run). Run ID: tmj_od3d_feasibility_20261005.
Дата протокола: 2026-10-05.
[Изменение](../../../docs/changes/003-tmj-od3d-pilot/README.md).

## Вопрос и критерий решения

Можно ли использовать экспертную разметку авторов для отдельного исследования
костных изменений без новой разметки нашими врачами?
Источник: [TMJ-OD3D V2](https://doi.org/10.57760/sciencedb.37727).
Коды положения проекта 1–6 к этой задаче не относятся.
Go требует опубликованного словаря всех кодов, правил пустых и сочетанных
меток, подтверждённых отрицательных примеров, связей пациент–сторона–снимки
и пригодного источника изображений. При отсутствии любого условия — no-go.

## Данные и разбиение

Предварительный аудит: весь локальный CSV V2; наружу только агрегаты и хэш.
Идентификаторы пациентов, строки метаданных, DICOM/JSON и previews остаются
в приватном хранилище. Наличие публичной лицензии не доказывает анонимность.
Проверить DICOM identifiers/private tags, текст в пикселях и возможность
реконструкции лица до экспорта; удаление тегов само по себе недостаточно.

После подтверждения codebook: отобрать до 24 пациентов детерминированно
по SHA256(namespace + source patient ID + seed=42), обеспечив сначала
покрытие каждого документированного кода и сочетаний, затем дополнить
до лимита. Сохранить приватный список и хэш. Не выбирать первые каталоги TAR.
Это выборка для разработки, не независимый test и не оценка распространённости.
Проверить геометрию, декодирование, соответствие side JSON, диапазоны срезов,
покрытие ROI и отсутствие дублей. Не использовать lesion boxes как независимый
автоматический локализатор: оценка с авторскими ROI является oracle-ROI.

Обучение на полной когорте потребует отдельного frozen split по пациентам:
обе стороны одного пациента всегда в одной группе; исключить дубли между
источниками. Долю test и поддержку классов определить после разрешения
семантики. Пациенты пилота могут входить только в development, не final test.

## Воспроизведение и ресурсы

Текущий этап: локальный CPU, без обучения. Для сетевого осмотра — не более
2 MiB начала публичного TAR, таймаут 30 секунд на запрос; полный архив не
скачивать. Прежний probe можно использовать как историческое свидетельство,
не объявлять повторно выполненным. SHA256 CSV фиксируется в результатах.

Следующий этап: загрузка до 24 выбранных исследований с лимитом 2 GiB
локальных данных; превышение — остановка и пересмотр объёма. В DataSphere
сначала подготовить приватный набор и точный план до запуска GPU. Не помещать
архив ~69 GiB в существующий payload с ограничением 5 GiB.

Пока не заданы mapping, пригодный preprocessing и новый entrypoint, текущий
position training runner запускать нельзя. Версии Python/PyTorch/CUDA,
commit, устройство, epochs/time cap, стоимость по актуальному тарифу и
checksums весов заполняются в отдельном протоколе обучения до подтверждения.
Платные VM/kernels/jobs на этом этапе не разрешены.

## Оценка будущего обучения

Если авторы подтверждают норму и патологию: начать с binary presence of
osseous abnormality. Baseline — константный прогноз по train prevalence;
основная метрика AUROC, дополнительно AUPRC, sensitivity/specificity при
пороге, выбранном только по validation. Доверительные интервалы — bootstrap
по пациентам. Для сочетаний патологий рассмотреть multilabel, не назначать
один произвольный класс. Выбор конкретного target и loss — после codebook.
Пилот из 24 пациентов не даёт достоверной оценки качества модели.

rows = list(csv.DictReader(b.decode("utf-8-sig").splitlines()))

print("sha256", hashlib.sha256(b).hexdigest())
print("rows/unique", len(rows), len({r["anonymous_id"] for r in rows}))
print("sides/missing/zero", len(labels), labels.count(""), labels.count("0"))
print("single_nonzero", sum(bool(x) and x != "0" and "|" not in x for x in labels))
print("combinations/patterns", sum("|" in x for x in labels), len(set(labels)))

## Решение

**Историческое решение до обнаружения авторского репозитория: no-go.** Нужен авторский
codebook: значения 0–6, правила отрицательного класса, пропусков и сочетаний,
связь label_L/label_R с JSON и версия схемы. После получения — пересмотреть
mapping, выполнить приватный пилот до 24 пациентов и подготовить отдельный
проверяемый план DataSphere с лимитом затрат. Тариф и время GPU сейчас не
оценены: без входной размерности и модели численная смета была бы догадкой.

Это не требует новой разметки от наших врачей, если авторские определения
и экспертные метки окажутся достаточны. При отсутствии словаря нельзя
считать задачу готовой к обучению или заменять коды предположениями.

## Разрешение семантики и продолжение

Позже 2026-10-05 найден [репозиторий автора](https://github.com/ZiTingW/TMJ-OD3D/blob/a4bce89c89b7175e330193f04a282887b5e3f8b0/README.md),
прямо ссылающийся на тот же ScienceDB набор. Опубликован codebook: 0 normal;
1 cortical erosion; 2 subchondral sclerosis; 3 subchondral cystic changes;
4 condylar flattening; 5 osteophyte; 6 other. Сочетания сохраняются,
пустая метка остаётся неизвестной. README SHA256:
`4963d94d18c956ddc0c4c026e66bcd61918200f868a29a4d4aca8e4fddca5e69`.
Авторский код использует включительные диапазоны InstanceNumber и доступные
срезы; не определяет физическое 3D заполнение пропусков. Его публикация
предшествует V2, поэтому соответствие CSV/JSON проверяется при импорте.

Новый технический smoke: 3 исследования, 6 сторон, совпадение CSV/JSON,
успешная подготовка slice bags без ошибок. Срезы действительно имеют разрывы,
поэтому выбран shared 2D CNN + pooling доступных ROI slices с одинаковым
preprocessing для всех кодов. Шесть приватных ROI визуально проверены:
видна анатомия мыщелка, видимых текстовых идентификаторов в этих кропах нет.
Это не клиническая оценка всей когорты. Исходные DICOM имеют непустые identity
теги, их значения не публикуются и в model payload не переносятся.

Цель расширена пользователем до готового запуска обучения. Реализуются
intake, preprocessing, patient holdout, binary/multilabel train/eval и
cloud bundle; полная когорта ещё готовится. Не объявлять smoke или код
готовностью всей когорты. GPU обучение не запускалось.

## Готовый запуск выбранной когорты

Пользователь остановил добор: 148 source cases, два annotation_side_conflict
исключены целиком по связанной с checkpoint review policy. Приняты 146 пациентов
и 289 сторон; missing_annotation=1, missing_label=2 отражены в exclusions.
Это prefix, не случайная репрезентативная выборка 1043 пациентов. Полный source
complete=false сохраняется; выбранная curated cohort подготовлена полностью.

Frozen split: train 102 пациента / 204 стороны, validation 22 / 43, test 22 / 42.
Development-only три пациента вне test. Все шесть pathological labels имеют
оба класса в train/validation. Test не использовался для выбора параметров и
не оценивался техническим smoke. Binary и multilabel real preflight прошли.

Два real bundle по ~61.9 MB собраны локально; exact manifests/bindings и frozen
split совпадают. Настоящий установленный DataSphere CLI проверил job schema и
paths. На двух development ROI в staged payload прошли forward/BCE/backward/step
обоих режимов на Torch 2.6.0 CPU; это не измерение качества. GPU не запускался.
Локальные проверки: 617 ML tests и 57 targeted curation tests пройдены.

План каждого запуска: Python 3.12, Torch 2.6.0+cu118, CUDA 11.8 image,
gt4.1 / один T4, batch 4, максимум 40 epochs / patience 8 / 4 часа обучения.
На 2026-10-05 ставка [168.48 RUB/hour](https://yandex.cloud/ru/docs/datasphere/pricing),
training-window estimate 673.92 RUB на режим; setup/storage/egress отдельно.
Это не hard money cap. Read-only API подтвердил доступ к проекту и разрешения
Jobs/gt4.1. Capacity GPU будет определяться в момент submit.

Exact project/profile, приватные plan SHA256 и команды confirm сохранены вне
Git. Остаётся подтверждение выбранного платного запуска. После завершения
проверяются training status, completion bindings/artifact digests и модель
сравнивается с constant train-prevalence baseline на frozen test один раз.
Исследование готово к запуску; улучшение качества ещё не измерено.
