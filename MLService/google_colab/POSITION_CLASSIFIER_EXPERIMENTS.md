# TMJ position classifier: эксперименты, проблемы, метрики

Сводка по цепочке обучения классификатора положения головки ВНЧС (сагитталь / фронталь) по КЛКТ-кропам. Источник истины по коду — ноутбуки в этом каталоге; ниже — контекст по экспериментам и **файлам аналитики**, которые присылались в чат (`training_analysis.json`, `training_analysis_v5.json` и т.д.; в git они могут не лежать).

---

## Версии пайплайна

| Версия | Ноутбук / секция | Суть |
|--------|------------------|------|
| **v1** | `train_position_classifier.ipynb` (ранний crop-пайплайн) | 3D CNN на кропах, 2 головы, 3 класса; сильный дисбаланс и переобучение |
| **v3** | тот же ноутбук | Взвешенный CE + label smoothing, аугментации, уменьшенная 3D-сеть; переобучение снизилось, **потолок mean acc ~0.734** сохранился |
| **v4** | `train_position_classifier_2d.ipynb` | 2D multi-view: frozen ResNet18 + классика (C) и fine-tune (A); **не превзошли ~0.734** на том же сплите |
| **v5** | `train_position_classifier_2d.ipynb`, секция 4b | Бинарные метки + multi-slice фичи + 5-fold CV по пациентам + PCA+SVM grid + ансамбль; отчёт в `training_analysis_v5.json` |
| **v6 (A+B)** | `train_binary_position_classifier.ipynb` | **Подход A:** детектор-кропы NIfTI 128³ (точный ROI вместо центрального кропа). **Подход B:** `BinaryFocalLoss(γ=2, α=auto)` + порог по Youden's J. Обучение на DataSphere V100. Baseline: mean acc ~0.68, коллапс сагиттали. |

## Что сделано в коде / инфраструктуре (по темам)

### 3D-ноутбук (`train_position_classifier.ipynb`)

- **DICOM:** `pydicom` + `pylibjpeg[libjpeg]`, явный `import pylibjpeg` перед декодированием; после установки — перезапуск сессии.
- **OOM Colab:** `num_workers=0`, `gc` / `empty_cache`, переход с полного объёма на **кропы после детектора**.
- **Препроцессинг:** потоковая загрузка DICOM по срезам (двухпроходный `preprocess_all_studies`), снижение пика RAM.
- **Анализ:** исправление `classification_report` / `confusion_matrix` с `labels=CLASS_LABELS`; **перед финальными матрицами — загрузка `best_model.pth`**, а не веса последней эпохи.

### 2D-ноутбук (`train_position_classifier_2d.ipynb`)

- **v5:** бинарные маппинги сагиттали/фронтали, multi-slice (5 позиций), `GroupKFold` + вложенный `GridSearchCV`, безопасные `pca__n_components` под размер inner-fold (исправление падений PCA).
- **Среды:** Colab / **Yandex DataSphere** / локально: `DATA_ROOT`, `WORK_ROOT`, `%pip`, `save_output()`, пути к кэшу фич и `experiments`.
- **DataSphere / данные:** скачивание zip с Drive из среды часто **недоступно**; рабочая схема — **ручной upload `tmj_data_lite.zip` + `unzip`**; датасет `#pragma dataset init` (≥2 GB для 172 кропов); `WORK_ROOT=/home/jupyter/project`.
- **Производительность:** переменные OpenMP/BLAS, `torch.set_num_threads`, батчинг извлечения фич, `BATCH_SIZE` и `DataLoader` workers вне Colab.
- **Визуализация входов:** пояснение, что в сеть идут **интенсивности КТ в кропе**, а не маски; гриды срезов и multi-slice.

## Аналитика по присланным JSON (интерпретация)

### v1 / v3 (3 класса, малый val)

- Сильный **дисбаланс** (класс «Normal» редкий), **переобучение** на v1; v3 его смягчил.
- **Mean accuracy ~0.734** как практический потолок при ~140 train-кропах и фиксированном patient split; метрики на **узком val (~32 кропа)** — шумные.

### v4 (2D, 3 класса)

- Подход C (SVM/RF/GB на frozen features) и A (fine-tune): **mean ~0.688**, потолок v1/v3 не побит.
- Вывод: узкое место — **объём и разметка данных**, а не только архитектура; плюс исправление бага «матрица по последней эпохе» для честного сравнения.

### v5 (`training_analysis_v5.json`)

- **Задача:** две бинарные головы (сагитталь: Anterior vs Non-anterior; фронталь: Non-lateral vs Lateral).
- **Оценка:** 5-fold по пациентам, OOF на **172 кропа** — честнее, чем один маленький val.
- **Лучший набор фич:** `mean_pooled` (1536-dim); concat на фронтали дал ~0.5 mean acc.
- **SVM (tuned):** в таблице сравнения **~0.680** mean (не сопоставимо 1:1 с v1/v3 из-за другой задачи и протокола, но порядок близок к v4).
- **Критично — сагитталь:** матрица OOF для лучшего SVM по сагиттали показывает **предсказание одного класса (все Anterior)**; accuracy ≈ доля мажоритарного класса; **Non-anterior: precision/recall/F1 = 0**. Модель для этой головы в текущем виде **не пригодна для интерпретации**.
- **Фронталь:** confusion и отчёт **осмысленные** (оба класса участвуют); это основной «рабочий» результат v5.
- **Ансамбль (voting):** по CV **слабее** SVM — в финале выбран SVM, это согласовано с метриками.
- **Данные в JSON:** `unique_patients: 40` при 172 кропах — если ожидалось больше пациентов, стоит проверить **полноту `tmj_data_lite` / manifest / labels**.

## Проблемы, с которыми столкнулись (и статус)

| Проблема | Статус |
|----------|--------|
| JPEG Lossless DICOM без плагинов | Исправлено (pylibjpeg + рестарт) |
| OOM в DataLoader / препроцессе | Исправлено (кропы, streaming, workers=0 в 3D) |
| Несоответствие классов в `classification_report` | Исправлено (`labels=`) |
| Матрицы по последней эпохе, не по best checkpoint | Исправлено в 3D и 2D |
| Малый val, шумные метрики | Частично: v5 — CV по пациентам |
| Потолок accuracy при малом датасете | **Открыто** — нужны данные или смена постановки |
| Коллапс класса на сагиттали (v5 binary SVM) | **Открыто** — метрики, веса, порог, другая склейка классов |
| gdown / Drive из DataSphere | **Обход:** lite zip + upload + unzip; датасет `#pragma` |
| `zipfile` в Python vs реальный zip | **Обход:** системный `unzip` |
| Мало места под датасет 1 GB | Решено: **2 GB** для `tmj_data` |
| Низкая утилизация RAM при sklearn/SVM | Ожидаемо; усилен CPU (потоки, батчи ResNet) |

## Что имеет смысл «добить» дальше

1. **Сагитталь (v5):** не оптимизировать blind accuracy — **macro-F1 / recall по minority**, focal loss или сильнее `class_weight`, калибровка порога, другая бинаризация или возврат к 3 классам только для сагиттали.
2. **Данные:** проверить согласованность **172 кропа / 40 пациентов** с полным когортой; при возможности — больше размеченных случаев.
3. **Сравнимость версий:** явно фиксировать в JSON протокол (3-class vs binary, split vs CV) чтобы не смешивать числа в одной таблице без оговорок.
4. **Продакшен-путь:** если остаётся DataSphere — документировать **upload zip + unzip + активация датасета** в README рядом с ноутбуком (этот файл — черновик такого описания).
