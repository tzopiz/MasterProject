# Патчи спецификации Backend

Активных нормативных патчей пока нет; пустые файлы-заготовки не создаются.
Патч нужен для изолированного согласованного дополнения или временного изменения
существующего требования. Общий процесс — [шаблоны](../../../../docs/spec/templates/README.md).

1. Создать каталог патча с единственным `README.md`; указать статус, мотив,
   затрагиваемые FR/NFR, исходное и изменённое поведение, границы действия.
2. Дать нормативному дополнению ID `PATCH-BE-<описание>` и явный HTML-якорь;
   приёмке — `TC-PATCH-BE-<описание>` с условием, действием и результатом.
3. Связать дополнение локальной ссылкой с его TC, а TC — с исходным требованием.
   Техническую реализацию и свидетельства хранить в инженерном слое.
4. Зарегистрировать патч в этом реестре и [трассировке](../traceability/README.md).
   Пробел без принятого решения остаётся GAP/OQ и не становится патчем.
5. После проверки внести согласованное поведение в постоянную спецификацию;
   отметить патч интегрированным или отменённым и сохранить историю решения.

Наличие согласованного патча не означает реализации или прохождения приёмки.
