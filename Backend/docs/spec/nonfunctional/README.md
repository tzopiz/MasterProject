# Нефункциональные требования Backend

Свойства относятся к принятой серии и ресурсу задачи. Это критерии приёмки,
а не утверждение о готовности эксплуатации; все проверки пока описаны.
Общие [соглашения](../../../../docs/spec/conventions/README.md) применяются к ID и статусам.

<a id="nfr-be-series-integrity"></a>
### NFR-BE-SERIES-INTEGRITY — Целостность серии

Backend не должен незаметно терять файлы между приёмом серии и передачей в ML.
Ошибка сохранения или чтения должна быть различима от обработки полной серии.
Это поддерживаемое намерение, которому текущий код не соответствует:
[GAP-BE-FILE-LOSS](../open-questions/README.md#gap-be-file-loss).
Приёмка: [TC-BE-SERIES-INTEGRITY](#tc-be-series-integrity).

<a id="tc-be-series-integrity"></a>
### TC-BE-SERIES-INTEGRITY — Недоступный файл

- Условие: серия содержит несколько файлов; запись или чтение одного завершается ошибкой.
- Действие: принять и обработать серию с контролируемой ошибкой хранилища.
- Результат: ошибка видима; обработка сокращённой серии не объявлена успехом полной серии.

<a id="nfr-be-upload-bound"></a>
### NFR-BE-UPLOAD-BOUND — Ограничение загрузки

Backend ограничивает размер принимаемой загрузки. Превышение действующего
ограничения отклоняется до создания задачи; лимит относится к телу запроса.
Фактический лимит маршрута и общий лимит приведены в [ai](../../ai/README.md#upload).
Целевой размер клинических серий не выбран: [OQ-BE-CAPACITY](../open-questions/README.md#oq-be-capacity).
Приёмка: [TC-BE-UPLOAD-BOUND](#tc-be-upload-bound).

<a id="tc-be-upload-bound"></a>
### TC-BE-UPLOAD-BOUND — Превышение лимита

- Условие: известен действующий лимит; подготовлен запрос больше него.
- Действие: передать запрос загрузки Backend.
- Результат: загрузка отклонена; задача и запуск ML для неё отсутствуют.

<a id="nfr-be-health-scope"></a>
### NFR-BE-HEALTH-SCOPE — Проверка живости

Проверка живости подтверждает ответ Backend. Она не подтверждает наличие
модели, доступность ML, полноту хранения или успешность сквозного анализа.
Смысл отдельной проверки готовности не задан: [OQ-BE-OPERATIONS](../open-questions/README.md#oq-be-operations).
Приёмка: [TC-BE-HEALTH-SCOPE](#tc-be-health-scope).

<a id="tc-be-health-scope"></a>
### TC-BE-HEALTH-SCOPE — Backend без ML

- Условие: Backend запущен; ML недоступен после запуска Backend.
- Действие: запросить проверку живости.
- Результат: ответ идентифицирует Backend и его живость; готовность ML не утверждается.
