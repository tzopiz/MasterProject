# Вклад Backend в интеграцию

Канонический сквозной контракт — [общая интеграция](../../../../docs/spec/integration/README.md).
Термины — [глоссарий](../../../../docs/spec/glossary/README.md),
оформление — [соглашения](../../../../docs/spec/conventions/README.md).
Этот раздел владеет обязательствами Backend на двух границах;
внутренний алгоритм ML и представление экрана iOS принадлежат их спецификациям.
Маршруты и поля зафиксированы в [ai](../../ai/README.md).

<a id="fr-be-client-compatibility"></a>
### FR-BE-CLIENT-COMPATIBILITY — Доступ клиента к задаче

Клиент должен иметь согласованный способ получить состояние и результат принятой
Backend задачи по её идентификатору. Обещание мгновенной готовности отсутствует.
Реализация цепочки несовместима: [маршрут](../open-questions/README.md#gap-be-client-route)
и [ожидание](../open-questions/README.md#gap-be-poll-window) требуют согласования.
Выбор исправления и длительности ожидания остаётся открытым.
Приёмка: [TC-BE-CLIENT-COMPATIBILITY](#tc-be-client-compatibility).

<a id="tc-be-client-compatibility"></a>
### TC-BE-CLIENT-COMPATIBILITY — Сквозное получение результата

- Условие: клиент и Backend используют согласованный маршрут и политику ожидания.
- Действие: загрузить серию, наблюдать задачу, получить успешный результат.
- Результат: клиент получает состояние и локализацию той же задачи без ошибки несовместимого маршрута.

<a id="fr-be-ml-correlation"></a>
### FR-BE-ML-CORRELATION — Согласованность ответа ML

Результат должен относиться к отправленной задаче; явная ошибка ML не означает
успешный анализ. Backend передаёт идентичность задачи вместе с серией.
Текущая обработка не проверяет возвращённую идентичность и состояние ML:
[GAP-BE-ML-VALIDATION](../open-questions/README.md#gap-be-ml-validation).
Приёмка: [TC-BE-ML-CORRELATION](#tc-be-ml-correlation).

<a id="tc-be-ml-correlation"></a>
### TC-BE-ML-CORRELATION — Ответ другой задачи

- Условие: ML получил серию одной задачи, но вернул успешный ответ с чужой идентичностью.
- Действие: обработать ответ ML.
- Результат: чужой результат не сохранён как успешный результат отправленной задачи;
  конкретный отказ требует решения по валидации, а не молчаливого принятия.
