# Пробелы и открытые вопросы Backend

`GAP` — известное расхождение или отсутствующая проверка реализации.
`OQ` — решение, которое нельзя вывести из кода. Запись здесь не разрешает новую
политику и не закрывает приёмку. Свидетельства собраны в [ai](../../ai/README.md).

<a id="gap-be-client-route"></a>
### GAP-BE-CLIENT-ROUTE — Несовместимый маршрут опроса

Клиент запрашивает отдельный статус, Backend предоставляет состояние вместе
с результатом. Требование: [FR-BE-CLIENT-COMPATIBILITY](../integration/README.md#fr-be-client-compatibility).
Решение: изменить клиентский опрос или интерфейс Backend; выбор не принят.

<a id="gap-be-poll-window"></a>
### GAP-BE-POLL-WINDOW — Несогласованное время ожидания

Опрос iOS ограничен 10 попытками с паузами 2 секунды; это не полный HTTP-дедлайн.
Backend допускает 10 минут на обращение к ML. Длительная задача может продолжаться
после отказа клиента. Требование: [FR-BE-CLIENT-COMPATIBILITY](../integration/README.md#fr-be-client-compatibility).

<a id="gap-be-file-loss"></a>
### GAP-BE-FILE-LOSS — Незаметное сокращение серии

Ошибки записи файлов подавляются, недоступные данные и нечитаемые файлы пропускаются.
Имена не проверяются на выход за каталог и коллизии; совпадающие имена могут перезаписать данные.
Это дефект границы хранения, а не допустимое правило приёма.
Требование: [NFR-BE-SERIES-INTEGRITY](../nonfunctional/README.md#nfr-be-series-integrity).

<a id="gap-be-input-validation"></a>
### GAP-BE-INPUT-VALIDATION — Непроверенный состав серии

Backend не проверяет DICOM-содержимое, принадлежность одной серии и геометрию.
Отбор по расширению при передаче ML не подтверждает валидность файлов.
Совместимость декодирования реальной multipart-загрузки не проверена выполнением.
Требование: [FR-BE-SERIES-SUBMIT](../functional/analysis/README.md#fr-be-series-submit).

<a id="gap-be-ml-validation"></a>
### GAP-BE-ML-VALIDATION — Непроверенный ответ ML

Идентичность и статус ML декодируются, но игнорируются. Без явной причины ошибки
возможен статус завершения без локализации; длины, границы координат и форма не проверяются.
Требования: [корреляция](../integration/README.md#fr-be-ml-correlation),
[прогресс](../functional/analysis/README.md#fr-be-task-progress).

<a id="gap-be-worker"></a>
### GAP-BE-WORKER — Ненадёжная фиксация исхода

Ошибка записи состояния ошибки может потеряться. Сохранение результата и статуса
не объединено в транзакцию; уникальность результата на задачу не обеспечена схемой.
Требование: [FR-BE-FAILURE-VISIBLE](../functional/analysis/README.md#fr-be-failure-visible).

<a id="oq-be-result-completeness"></a>
### OQ-BE-RESULT-COMPLETENESS — Полнота результата

Нужно ли расширять [текущий контракт ML](../../../../MLService/docs/spec/integration/README.md#fr-ml-int-localization-exchange),
где успех содержит обе стороны и размер объёма, поддержкой частичной локализации?
Если да, как обозначать такой исход для клиента? До решения неполный ответ
не является согласованным успешным результатом. Optional-поля кода не задают эту политику.

Ответ: ожидается решение владельца.

<a id="oq-be-data-policy"></a>
### OQ-BE-DATA-POLICY — Доступ и срок хранения

Кто вправе загружать и читать задачи, как изолировать пользователей, сколько хранить
серии и результаты, как удалять их? Авторизация и автоматическая очистка не реализованы.
Сроки, роли и механизм развёртывания здесь не назначаются.

Ответ: ожидается решение владельца.

<a id="oq-be-operations"></a>
### OQ-BE-OPERATIONS — Надёжность обработки

Нужны ли восстановление задач, повторы, отмена и отдельная готовность сервиса?
Какие гарантии после рестарта и сбоя хранилища требуются? Долговечный исполнитель не выбран.

Ответ: ожидается решение владельца.

<a id="oq-be-capacity"></a>
### OQ-BE-CAPACITY — Размер и длительность анализа

Каковы целевые размеры серий, параллелизм, время анализа и политика ожидания клиента?
Текущие числовые ограничения — свойства кода, не измеренные пределы работоспособности.

Ответ: ожидается решение владельца.
