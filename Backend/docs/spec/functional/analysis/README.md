# Задача анализа серии DICOM

Участники: клиент передаёт серию; Backend организует обработку;
ML Service возвращает локализацию ВНЧС. Единица работы — задача анализа серии.
Термины определены в [общем глоссарии](../../../../../docs/spec/glossary/README.md).
Техническое представление — в [инженерных свидетельствах](../../../ai/README.md).
Все TC ниже описаны для будущей проверки; выполненных HTTP-проверок нет.

<a id="fr-be-series-submit"></a>
### FR-BE-SERIES-SUBMIT — Передача серии

Backend принимает непустой набор файлов серии DICOM для отдельной задачи анализа.
Принятие загрузки означает создание задачи, а не готовность локализации.
Код содержит этот сценарий; совместимость реальной загрузки не проверена.
Приёмка: [TC-BE-SERIES-SUBMIT](#tc-be-series-submit).

<a id="tc-be-series-submit"></a>
### TC-BE-SERIES-SUBMIT — Принятая серия

- Условие: непустая доступная серия, работающие Backend и хранилище.
- Действие: клиент передаёт серию на анализ.
- Результат: клиент получает идентификатор новой задачи и может запросить её состояние.

<a id="fr-be-empty-series"></a>
### FR-BE-EMPTY-SERIES — Отказ пустой загрузке

Backend отклоняет набор без файлов; задача анализа для него не создаётся.
Проверка пустого набора есть в коде; некорректная форма запроса — отдельный случай.
Приёмка: [TC-BE-EMPTY-SERIES](#tc-be-empty-series).

<a id="tc-be-empty-series"></a>
### TC-BE-EMPTY-SERIES — Пустой набор

- Условие: запрос допускает декодирование, но набор файлов пуст.
- Действие: клиент отправляет его на анализ.
- Результат: отказ с причиной отсутствия файлов; новая задача отсутствует.

<a id="fr-be-task-identity"></a>
### FR-BE-TASK-IDENTITY — Идентичность задачи

Каждая принятая загрузка получает отдельный идентификатор; состояние и результат
относятся к этой задаче. Дедупликация повторных загрузок не заявлена.
Приёмка: [TC-BE-TASK-IDENTITY](#tc-be-task-identity).

<a id="tc-be-task-identity"></a>
### TC-BE-TASK-IDENTITY — Две загрузки

- Условие: доступны две корректные загрузки одной или разных серий.
- Действие: создать две задачи и запросить каждую по возвращённому идентификатору.
- Результат: идентификаторы различаются; ответы относятся к запрошенным задачам.

<a id="fr-be-task-progress"></a>
### FR-BE-TASK-PROGRESS — Состояние обработки

Backend различает ожидание, обработку, завершение и ошибку задачи.
Сохранение результата предшествует объявлению завершения; ожидание или обработка
не означают готовность результата. Клиент может не наблюдать краткие промежуточные состояния.
Проверка успешности ответа ML неполна: [GAP-BE-ML-VALIDATION](../../open-questions/README.md#gap-be-ml-validation).
Приёмка: [TC-BE-TASK-PROGRESS](#tc-be-task-progress).

<a id="tc-be-task-progress"></a>
### TC-BE-TASK-PROGRESS — Успешная обработка

- Условие: серия принята, ML возвращает успешную локализацию для этой задачи.
- Действие: наблюдать задачу во время обработки и после её окончания.
- Результат: задача достигает завершения; при завершении сохранённый результат доступен.

<a id="fr-be-result-access"></a>
### FR-BE-RESULT-ACCESS — Получение состояния и результата

Backend предоставляет состояние существующей задачи и доступный результат
через один ресурс задачи. Отсутствие результата до завершения допустимо.
Несовместимый опрос клиента отмечен в [GAP-BE-CLIENT-ROUTE](../../open-questions/README.md#gap-be-client-route).
Приёмка: [TC-BE-RESULT-ACCESS](#tc-be-result-access).

<a id="tc-be-result-access"></a>
### TC-BE-RESULT-ACCESS — Повторный запрос задачи

- Условие: есть ожидающая задача и задача с сохранённым результатом.
- Действие: запросить каждую по её идентификатору.
- Результат: оба ответа содержат состояние соответствующей задачи; готовый результат доступен.

<a id="fr-be-localization"></a>
### FR-BE-LOCALIZATION — Смысл результата

Backend передаёт полученные от ML сведения о левом и правом ВНЧС и размере объёма,
не меняя систему координат. Центр и границы заданы в вокселях объёма ML;
они не являются миллиметровыми измерениями или клиническим заключением.
Поддержка отдельного успешного частичного результата требует решения: [OQ-BE-RESULT-COMPLETENESS](../../open-questions/README.md#oq-be-result-completeness).
Приёмка: [TC-BE-LOCALIZATION](#tc-be-localization).

<a id="tc-be-localization"></a>
### TC-BE-LOCALIZATION — Передача локализации

- Условие: ML вернул известные корректные координаты обеих сторон и размер объёма.
- Действие: завершить обработку и получить результат задачи.
- Результат: значения, стороны и оси совпадают с ответом ML; преобразования в миллиметры нет.

<a id="fr-be-failure-visible"></a>
### FR-BE-FAILURE-VISIBLE — Ошибка анализа

При явной ошибке обработки задача переходит в состояние ошибки с доступной причиной.
Ошибка не выдаётся за успешную локализацию. Код обрабатывает явную причину ML и
исключения; запись самой ошибки может быть потеряна: [GAP-BE-WORKER](../../open-questions/README.md#gap-be-worker).
Приёмка: [TC-BE-FAILURE-VISIBLE](#tc-be-failure-visible).

<a id="tc-be-failure-visible"></a>
### TC-BE-FAILURE-VISIBLE — Отказ ML

- Условие: задача принята, запись в хранилище доступна, ML возвращает явную ошибку.
- Действие: дождаться обработки и запросить задачу.
- Результат: состояние ошибки и причина доступны; завершение анализа не заявлено.

<a id="fr-be-task-lookup"></a>
### FR-BE-TASK-LOOKUP — Некорректная или неизвестная задача

Backend различает некорректный идентификатор и корректный идентификатор
несуществующей задачи. Ни в одном случае результат другой задачи не возвращается.
Приёмка: [TC-BE-TASK-LOOKUP](#tc-be-task-lookup).

<a id="tc-be-task-lookup"></a>
### TC-BE-TASK-LOOKUP — Ошибка поиска

- Условие: некорректный идентификатор и корректный идентификатор без задачи.
- Действие: запросить состояние каждого.
- Результат: различимые отказы: некорректный запрос и задача не найдена.
