## 🚀 Быстрый старт (5 минут)

### Шаг 1: Запустите Backend

```bash
cd Backend
swift build
swift run App
```

Backend запустится на `http://localhost:8080`

### Шаг 2: Запустите ML Service (в новом терминале)

```bash
cd MLService
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python app.py
```

ML Service запустится на `http://localhost:8001`

### Шаг 3: Проверьте работу

```bash
# Проверить Backend
curl http://localhost:8080/health

# Проверить ML Service
curl http://localhost:8001/health
```

Если оба ответили статусом "ok" - всё работает! 🎉

## 🤔 Частые вопросы

### Q: У меня нет обученной модели сегментации. Что делать?
A: Проект работает в "dummy mode" - генерирует тестовые маски и параметры. Это позволяет разрабатывать iOS приложение и тестировать API без модели. Модель можно добавить позже.

### Q: Где взять DICOM файлы для тестирования?
A: Используйте публичные датасеты (например, The Cancer Imaging Archive) или анонимизированные данные из вашей работы в бакалавриате.

### Q: Можно ли использовать модель из бакалавриата?
A: Да! Конвертируйте её в PyTorch формат (.pth) и поместите в `MLService/models/`. См. [NEXT_STEPS.md](NEXT_STEPS.md) раздел "Обучение модели".

### Q: Как разрабатывать iOS приложение?
A: Backend и ML Service уже готовы и работают. Создайте iOS проект в Xcode и используйте API endpoints для загрузки файлов и получения результатов. Примеры в [API_EXAMPLES.md](API_EXAMPLES.md).

### Q: Нужно ли всё писать на Swift?
A: Нет, текущая архитектура оптимальна: Swift для iOS и Backend (ваша цель), Python для ML (стандарт индустрии). Это позволяет подтянуть Swift и использовать лучшие инструменты для ML.

### Q: Как это развернуть?
A: Есть бесплатные варианты (Render, Railway, Fly.io). Подробности в [DEPLOYMENT.md](DEPLOYMENT.md).
