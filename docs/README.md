# Разработка MasterProject по спецификациям

У системы три самостоятельных владельца поведения: **Backend**, **MLService** и **iOS-клиент**. У каждого — свой набор требований, приёмочных сценариев, пробелов и инженерных сведений. iOS является логическим компонентом, а не HTTP-сервисом. Общие правила и межкомпонентные договорённости находятся в [спецификации системы](spec/README.md).

## Порядок работы

1. Прочитать правило затронутой темы, его приёмку и применимые дополнения компонента; затем инженерные сведения и нужные исходники.
2. Если поведение уже задано правилом, восстановить его в коде либо согласовать изменение намерения и обновить правило с приёмкой. Если поведение ещё не описано, применить порядок «сначала код» из общих правил.
3. Для локальной правки достаточно тематического правила и сценария. Отдельная спецификация функции и технический план нужны при существенном дизайне или координации; отдельный change-документ на каждую правку не требуется.
4. Проверить реализацию по приёмочным случаям, обновить инженерные сведения и связи с проверками. В PR указать ID/пути правил, фактические команды и результаты; невыполненные проверки назвать явно.
5. Запустить `python3 scripts/check_specs.py` из корня. Это проверка структуры документов, ссылок, якорей и ID; она не заменяет тесты поведения и оценку модели.

Спецификация описывает согласованное намерение. Инженерный справочник описывает текущую реализацию. Протокол эксперимента или отчёт проверки содержит наблюдённый результат. Эти три вида утверждений не подменяют друг друга.

## Документы и инструменты

В каждом каталоге Markdown-файл называется `README.md`; корневой `AGENTS.md` — единственное исключение. Поэтому отдельная тема является каталогом с README. Для работы достаточно Git и редактора; обязательного генератора или внешнего CLI нет.

Общие правила не копируются в три компонента. Требования и сценарии принадлежат своей теме; интеграционные соглашения ссылаются на обе стороны границы. Новая локальная проверка не требует изменения всех центральных таблиц. Историю чатов, ход ветки и отчёты запусков не помещают в постоянные правила.
