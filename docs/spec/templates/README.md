# Общие шаблоны

Шаблоны применяются по необходимости согласно [правилам ведения](../conventions/README.md). Локальное изменение существующего правила обычно обходится без отдельного документа. Все файлы называются `README.md`; незаполненные подсказки удаляются перед принятием спецификации. Подставлять предметные факты только своего компонента.

## Спецификация существенной функции

Место: `<component>/docs/spec/features/<topic>/README.md`. Если функция меняет существующее правило, её документ не создаёт второго нормативного владельца: основное правило обновляется, а функция ссылается на него.

```markdown
# Название функции

Статус намерения: предложение / согласованная цель / поддерживаемый контракт.
Границы: пользовательский или исследовательский результат; явные исключения.
Владелец: компонент, владелец входных данных и результат для потребителя.

## Сценарий

Кому и зачем нужно поведение; самостоятельно наблюдаемый результат.

## Правила и приёмка

<a id="fr-owner-topic-result"></a>
### FR-OWNER-TOPIC-RESULT — Наблюдаемый результат

Если выполняется условие, то система выдаёт результат. Ошибки и пропуски,
если они влияют на поведение, описаны явно.
Приёмка: [TC-OWNER-TOPIC-RESULT](#tc-owner-topic-result).

<a id="tc-owner-topic-result"></a>
### TC-OWNER-TOPIC-RESULT — Проверка результата

Если заданы входы; когда выполняется действие; тогда наблюдается результат.
Автоматизация: ссылка на реальный тест и его пределы либо «не реализована».

## Открытые решения

Только существенные вопросы, которые нельзя установить по источникам;
ответ владельца или явное ожидание решения. Не придумывать показатели успеха.
```

`OWNER` заменяется на `BE`, `ML` или `IOS`. Планируемые проверки не выдаются за существующие или выполненные. Ссылки на инженерные сведения помогают найти реализацию, не заменяя формулировки поведения.

## Технический план

Место при необходимости: `<component>/docs/spec/features/<topic>/plan/README.md`. Для межкомпонентного изменения план определяет зависимость шагов и владельцев; правила остаются в соответствующих компонентах.

```markdown
# План реализации функции

Требования: относительные ссылки и ID согласованных правил.

## Дизайн

Владельцы операций, поток входов/результата, интерфейсы, точные пути файлов,
совместимость и существенные решения. Не повторять спецификацию поведения.

## Последовательность

- [ ] Релевантная регрессионная проверка либо объяснение, почему новая не нужна.
- [ ] Ограниченное изменение в указанных файлах с названными зависимостями.
- [ ] Проверка контракта, обновление инженерных сведений и связей с приёмкой.

## Проверка

Команды/ручные сценарии, ожидаемый результат, нужные данные и ограничения.
Принципы системы проверяются до и после выбора дизайна.
Фактические результаты и ход PR хранятся в PR, а не в постоянном правиле.
```

## Дополнение

Место: `<component>/docs/spec/patches/<topic-change>/README.md`. Дополнение становится частью действующего контракта и не может отменять уже действующее правило.

```markdown
# Новое поведение в существующем сценарии

Область: конкретный сценарий/интерфейс и ссылка на действующее правило.

<a id="patch-owner-topic-change"></a>
### PATCH-OWNER-TOPIC-CHANGE — Новое условие и результат

Если / Когда / Тогда; существенные пустые и ошибочные случаи.
Приёмка: [TC-PATCH-OWNER-TOPIC-CHANGE](#tc-patch-owner-topic-change).

<a id="tc-patch-owner-topic-change"></a>
### TC-PATCH-OWNER-TOPIC-CHANGE — Приёмка дополнения

Конкретные входы и наблюдаемый исход. Ссылка на тест с границей покрытия
либо явно указанное отсутствие автоматизации; без заявления о запуске.
```

## Проверка перед завершением

- Правило имеет одного владельца, стабильный ID и наблюдаемую приёмку.
- Цель, код и фактически выполненная проверка различимы; пробелы не скрыты.
- Изменённые границы согласованы с потребителями, вопросы не решены выдуманными допущениями.
- Ссылки, якоря и прослеживаемость проверены; для документов запуск приложения не требуется.
- Дополнение применимо по выбранному порядку работы и не противоречит главе.

Для ML-запуска используется отдельный [протокол эксперимента](../../../MLService/experiments/template/README.md).
