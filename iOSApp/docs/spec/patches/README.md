# Патчи требований iOS

Этот раздел используется для нормативных уточнений поведения, впервые определённого при реализации.
Общие правила оформления и приоритета заданы в [соглашениях](../../../../docs/spec/conventions/README.md) и [шаблонах](../../../../docs/spec/templates/README.md).

## Когда нужен патч

Подход «сначала код» допустим только там, где действующая спецификация ещё не задаёт правило.
Если решение затрагивает уже описанный интерфейс, его нормативное уточнение обязательно должно быть оформлено патчем и связано с приёмкой.
Патч не разрешает нарушить существующее требование или изменить парное соглашение односторонне.
Известный GAP исправляется относительно действующего правила, а не переименовывается в новое желаемое поведение.

## Идентификаторы и содержание

Патч получает устойчивый ID `PATCH-IOS-*`, а его приёмка — `TC-PATCH-IOS-*`.
Он содержит область действия, недостающее правило, целевое поведение, связи с FR/NFR и наблюдаемый критерий приёмки.
Критерий задаёт предусловие, действие и результат; исходник сам по себе не заменяет проверку.
При затрагивании общей границы нужна ссылка на соответствующее уточнение общего интеграционного контракта.
Согласованное правило включается в постоянную спецификацию с сохранением трассировки ID.

Нормативных патчей iOS в этом разделе пока нет.
План отдельной будущей функции необязателен и не заменяет требования или обязательный патч интерфейса.
