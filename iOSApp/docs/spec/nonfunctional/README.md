# Нефункциональные требования iOS

Требования ограничивают работу клиента с данными и пользовательским интерфейсом.
Численные бюджеты не определены: [OQ-IOS-WAITING-POLICY](../open-questions/README.md#oq-ios-waiting-policy), [OQ-IOS-SERIES-BUDGET](../open-questions/README.md#oq-ios-series-budget).

<a id="nfr-ios-data-boundary"></a>
### NFR-IOS-DATA-BOUNDARY — Граница доступа к данным

Клиент должен читать только файлы серии, явно выбранной пользователем.
Передача допускается только после явного запуска анализа и только в Backend, предназначенный для этой операции.
Выбор папки не разрешает сканирование соседних папок, скрытую загрузку или отправку других данных устройства.
Клиент не должен выводить содержимое DICOM или идентифицирующие медицинские данные в сообщения ошибок и диагностические сообщения.
Имена выбранных файлов могут показываться пользователю в интерфейсе выбора; это не разрешает их дополнительную передачу вне согласованного запроса.

Приёмка: [TC-IOS-DATA-BOUNDARY](#tc-ios-data-boundary).

<a id="tc-ios-data-boundary"></a>
### TC-IOS-DATA-BOUNDARY — Граница передачи

Предусловие: на устройстве есть выбранная серия и файлы вне неё.
Действие: выбрать серию без запуска, затем явно запустить анализ и проверить состав обращения и диагностических сообщений.
Наблюдаемый итог: выбор не передаёт данные, запуск передаёт только выбранную серию назначенному Backend; содержимое DICOM и идентифицирующие медицинские данные не раскрываются в сообщениях.

<a id="nfr-ios-file-access"></a>
### NFR-IOS-FILE-ACCESS — Корректный доступ к выбранным файлам

Системное разрешение на доступ должно действовать в течение фактического чтения выбранных файлов.
Полученный доступ освобождается после завершения чтения, включая путь ошибки.
Успешное перечисление файлов не считается доказательством возможности прочитать их позже.
Если разрешение утрачено или файл недоступен, клиент должен завершить подготовку ошибкой согласно FR-IOS-COMPLETE-SERIES.
Клиент не должен обходить отказ системы или молча заменять выбранную серию доступной частью.

Приёмка: [TC-IOS-FILE-ACCESS](#tc-ios-file-access).

<a id="tc-ios-file-access"></a>
### TC-IOS-FILE-ACCESS — Системный файловый доступ

Предусловие: серия выбрана через системный интерфейс у поставщика файлов с ограниченным доступом.
Действие: прочитать всю серию; повторить с отказом доступа и ошибкой чтения в середине подготовки.
Наблюдаемый итог: разрешение охватывает фактическое чтение, освобождается в обоих исходах; отказ не обходится, частичная серия не загружается.

<a id="nfr-ios-accessible-ui"></a>
### NFR-IOS-ACCESSIBLE-UI — Доступное состояние интерфейса

Чтение файлов, передача и ожидание не должны блокировать пользовательский интерфейс на всё время операции.
Пользователь должен понимать, выполняется ли операция, завершилась ли она и доступен ли новый запуск.
Состояния успеха, ошибки и выполнения должны быть доступны текстом и не различаться только цветом.
Основные действия и обозначения сторон результата должны иметь понятные названия для средств доступности.
Недопустимый ответ Backend не должен приводить к аварийному завершению интерфейса.

Приёмка: [TC-IOS-ACCESSIBLE-UI](#tc-ios-accessible-ui).

<a id="tc-ios-accessible-ui"></a>
### TC-IOS-ACCESSIBLE-UI — Интерфейс и безопасный отказ

Предусловие: включены средства доступности, чтение или серверная обработка занимает заметное время.
Действие: запустить анализ, проверить навигацию и озвучивание состояния; вернуть повреждённый ответ.
Наблюдаемый итог: интерфейс остаётся доступным, действия и стороны имеют названия, состояние понятно без цвета; повреждённый ответ завершает операцию ошибкой без аварии.
