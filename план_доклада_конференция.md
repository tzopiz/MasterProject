# План доклада на конференцию: начальный этап проекта AI Doctor — анализ ВНЧС

**Объём:** ~5 листов A4, шрифт Times New Roman 14 pt (текст), 16 pt (заголовки), межстрочный интервал 1,5 (ориентировочно 12–14 тыс. знаков с пробелами).

**Фокус:** первые шаги, постановка задачи, что уже сделано. Проект в процессе; доклад — о начальном этапе.

## 1. Введение и актуальность (≈0,7–1 стр.)

**О чём писать:**

- **Тема:** интеллектуальная система для автоматизированного анализа височно-нижнечелюстного сустава (ВНЧС) по данным конусно-лучевой компьютерной томографии (КЛКТ) с использованием методов глубокого обучения.
- **Актуальность:** заболевания ВНЧС широко распространены; КЛКТ — основной метод визуализации; ручной анализ 3D-снимков трудоёмок и субъективен; ИИ даёт возможность автоматизации и стандартизации.
- **Контекст:** магистерская программа «Искусственный интеллект в медицине»; предшествующие работы — 2D U-Net для сегментации на сагиттальных срезах (высокий Dice для головки, ограничения: ручной выбор срезов, только 2D, малый датасет, отсутствие интеграции в приложение).
- **Цель доклада:** представить постановку задачи и результаты начального этапа разработки системы.

**Источники в проекте:** `Nir/otchet_nir_magistratura_sem1.md` (Введение, актуальность, предпосылки), `тезисы_конференция.txt` (цель исследования).

## 2. Постановка задачи (≈1–1,2 стр.)

**О чём писать:**

- **Общая задача:** система автоматизированной оценки состояния ВНЧС по данным КЛКТ. Вход: DICOM-исследование (серия 2D-срезов). Выход: диагностическое заключение по левому и правому суставу (норма / патология; в перспективе — расширение классов).
- **Исходные данные:** типичное КЛКТ — 500–600 DICOM-файлов, объём после реконструкции порядка 576×768×768 вокселей, единицы Хаунсфилда; нижняя треть лица, билатеральное расположение ВНЧС.
- **Почему двухэтапный подход:** прямой анализ полного 3D-объёма нереалистичен (объём данных, память GPU). Этап 1 — локализация центров левого и правого суставов (регрессия координат по даунсемплированному объёму). Этап 2 — анализ локальных областей (ROI): сегментация и/или классификация (норма/патология).
- **Требования к системе (кратко):** полная автоматизация процесса, клинически приемлемая точность локализации и классификации, приемлемое время обработки, удобный интерфейс и поддержка DICOM.

**Источники:** `Nir/otchet_nir_magistratura_sem1.md` (раздел «Постановка задачи», описание данных, целевые классы, подход к решению, требования).

## 3. Архитектура системы и первые шаги реализации (≈1–1,2 стр.)

**О чём писать:**

- **Выбор архитектуры:** распределённая система (вместо монолита): тяжёлые ML-вычисления на сервере с GPU, лёгкий клиент для врача.
- **Три компонента:**
  - **iOS-приложение (Swift/SwiftUI):** загрузка и локальный парсинг DICOM, визуализация снимков и результатов (координаты, bbox, при необходимости — метки нормы/патологии).
  - **Backend (Swift Vapor):** REST API, управление задачами анализа, хранение в SQLite, асинхронный вызов ML-сервиса.
  - **ML Service (Python, FastAPI):** загрузка DICOM, препроцессинг, инференс моделей (детекция, далее — сегментация/классификация), возврат результатов в JSON.
- **Что уже сделано на начальном этапе:**
  - Спроектирована и реализована схема взаимодействия (REST, контракты данных).
  - Backend: загрузка DICOM, создание задач, вызов ML-сервиса, сохранение результатов.
  - ML Service: пайплайн обработки DICOM, интеграция модели детекции TMJ.
  - iOS: модульная структура (MAA), парсинг DICOM, экраны загрузки и отображения результатов детекции (координаты, bbox).
- **Форматы и потоки данных:** DICOM на входе; JSON для API (идентификатор задачи, координаты центров суставов, bbox, при наличии — класс и уверенность).

**Источники:** `README.md`, `PROJECT_PRESENTATION.md`, `Nir/otchet_nir_magistratura_sem1.md` (Глава 1, раздел 1.3), `TMJ_DETECTION_SETUP.md`.

## 4. Алгоритмы машинного обучения: детекция ВНЧС (≈1–1,2 стр.)

**О чём писать:**

- **Задача первого этапа:** автоматическая локализация центров левого и правого ВНЧС в полном 3D-объёме КЛКТ (регрессия координат).
- **Модель детекции:** 3D CNN (TMJDetectorLarge), энкодер + регрессионная «голова». Вход: даунсемплированный объём (например, 96×128×128). Выход: координаты центров обоих суставов (нормализованные или в вокселях). Размер модели — порядка 14,4 млн параметров.
- **Данные и обучение:** датасет из 37 аннотированных КЛКТ-исследований; разметка координат центров суставов (инструменты разметки в проекте). Аугментации: сдвиги, повороты, масштабирование с пересчётом целевых координат, яркостные искажения, шум. Функция потерь: L1 (MAE) или Smooth L1. Оптимизатор Adam, ранняя остановка.
- **Результаты начального этапа:** модель обучается и проходит валидацию; на валидации достигнута ошибка локализации порядка 97 px MAE (целевой ориентир — дальнейшее снижение, например &lt; 50 px или перевод в мм с учётом разрешения снимка). Стабильная сходимость обучения, детекция обоих суставов на полных 3D-снимках.
- **Интеграция:** модель встроена в ML Service; по координатам вырезаются ROI для последующего этапа (сегментация 3D U-Net, классификация).

**Источники:** `Nir/otchet_nir_magistratura_sem1.md` (Глава 2, разделы 2.1, 2.3), `PROJECT_PRESENTATION.md`, `тезисы_конференция.txt`, `TMJ_DETECTION_SETUP.md`, `MLService/models/tmj_detector.py`, `MLService/train_detector.py`.
