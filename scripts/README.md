# Проверка спецификаций

Из корня репозитория, Python 3.10+ и Git; внешние пакеты и данные не нужны:

```bash
python3 scripts/check_specs.py --self-test
python3 scripts/check_specs.py
```

Вход — `git ls-files --cached --others --exclude-standard`: отслеживаемые и новые неигнорируемые файлы текущей рабочей копии. Индекс Git не изменяется. Локальный игнорируемый файл не считается доступной целью ссылки. При выборочном коммите необходимо включить новые документы-цели; CI повторяет проверку в checkout коммита.

Проверяются:

- Политика README.md для всех Markdown в Git, с исключением корневого AGENTS.md.
- Наличие общих документов и трёх самостоятельных наборов спецификаций.
- Локальные inline-ссылки и Markdown-якоря в спецификациях, инженерных справочниках и протоколе-шаблоне.
- Уникальность определений ID и явных якорей, принадлежность ID компоненту, определённость ссылок на ID.
- Связь каждого FR/NFR/PATCH с TC, определённым в той же теме.

Примеры внутри fenced code blocks пропускаются; сетевые URL, произвольный Markdown, якоря исходников и доступность внешних ресурсов не проверяются. Самопроверка содержит корректный пример и десять вариантов отказа, включая файл, существующий только локально вне инвентаря Git.

Это структурная проверка: она не доказывает полноту требований, правдивость описания тестов, успешное выполнение TC, качество моделей или отсутствие персональных данных. Эти свойства проверяются ревью и применимыми сценариями [процесса разработки](../docs/README.md).

Код выхода: 0 — проверка пройдена, 1 — нарушение/ошибка чтения, 2 — неверные аргументы. Workflow Specifications запускает обе команды независимо от затронутого компонента.
